# ntt-gpu

一个 GPU 程序，用来乘两个超长的十进制整数——长到普通计算器、普通大整数库都算不动的程度。

| 每个数多少位 | 用时 |
|---|---:|
| 6000 万位 | 0.26 秒 |
| 2.68 亿位 | 1.2 秒 |
| 5.37 亿位（上限） | 2.3 秒 |

位数指的是一个数有几位数字。结果位数是输入的两倍：5.37 亿位 × 5.37 亿位，得到
10.7 亿位的结果。

这些是 `--bench` 的数字，不算读写文件，也不含显卡冷启动（约 0.13 秒）。真拿文件跑
6000 万位，读入加写出再多 0.25 秒左右。机器是 GTX 1660 SUPER 6 GB + i3-12100F。

## 怎么用

第一步，装好 **Visual Studio 2022**（勾选"使用 C++ 的桌面开发"）和 **CUDA 12 或 13**。

第二步，在这个目录下编译：

```powershell
./build.ps1
```

没有别的参数。脚本自己找编译器和显卡，成功后会告诉你生成了 `ntt_gpu.exe`。

第三步，准备一个文本文件，里面**正好两行**数字，然后：

```powershell
./ntt_gpu.exe                  # 读 input.txt，结果写 output.txt
./ntt_gpu.exe 甲.txt 乙.txt     # 自己指定输入输出文件名
./ntt_gpu.exe 甲.txt -          # 结果直接打到屏幕上
```

想测速就不写文件：`./ntt_gpu.exe --bench 200000000`。

## 屏幕上会看到什么

跑两个 6000 万位的数（输入文件 120 MB），会看到：

```
left_digits=60000000
right_digits=60000000
result_digits=120000000
total_ms=542
stage_ms=input 151 startup 157 gpu 96 merge 47 carry 42 write 111
```

前四行是两边的位数、结果的位数、总耗时（毫秒）。最后一行是分段耗时：

- `input` 读文件并转成内部格式
- `startup` 显卡初始化，和 `input` 同时进行，所以这两个数加起来会比 `total_ms` 大
- `gpu` 显卡计算
- `merge` 把三份结果合成一份
- `carry` 进位
- `write` 转回十进制并写出

## 能算多大

一个数的位数上限是 **5.37 亿**。

这不是显存决定的，是数学决定的：这个算法需要一个长度只能是 2 的幂的变换，而 32 位
整数能支持的最长长度是 2^27 点，一个点对应四位数字，于是上限就是 `4 × 2^27`。

图形显存不够时会直接告诉你差多少，不会崩。6 GB 的卡跑满不需要调任何参数。

## 文件都在干什么

| 文件 | 干什么 | 需要看懂吗 |
|---|---|---|
| `ntt_gpu.cu` | 程序入口：读文件、调度、写结果 | 想改用法就看 |
| `decimal.cu` | 十进制和内部格式互转，合成最终答案 | 可选 |
| `ntt.cu` | 显卡上的变换 | 不用，除非你想改算法 |
| `ntt.h` | 三个文件共用的声明 | 可选 |

## 里面怎么做的（看不懂可以跳过）

1. 把十进制数字**八个一组**，一组存成一个 32 位整数（相当于改成 `10^8` 进制）。
2. 用快速傅里叶变换的整数版本（NTT）在显卡上算卷积。这是整个程序唯一耗时的部分。
3. 一个素数装不下结果，所以用三个素数各算一遍，再用中国剩余定理拼回精确值。
4. 从低位到高位进位，转回十进制输出。

## 测试

```powershell
python test.py            # 22 个用例，几秒钟
python test.py --fuzz 200 # 再加 200 组随机尺寸
python test.py --huge     # 再加 5.37 亿位上限用例（要 4 GB 内存）
```

标准答案是 Python 自带的大整数，逐字节对比。

## 两个坑

- **源码必须保持 UTF-8 带 BOM**。编辑时别让编辑器把 BOM 去掉：编译器按系统代码页
  读源文件，没有 BOM 时中文注释会让它报 `missing closing quote`。
- **CUDA 13 起不支持 Maxwell（sm_50）及更早的显卡**，老卡要留在 CUDA 12.x。

## 为什么提示文字是英文

程序打印的用法和报错都是英文。中文在 Windows 控制台里经常乱码——同一个程序在
PowerShell、cmd、重定向到文件三种情况下会被用不同的编码解码。英文没有这个问题，
任何终端都读得懂。注释和这份文档是中文，那些是打开文件看的东西。
