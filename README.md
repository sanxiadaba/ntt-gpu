# ntt-gpu

用 CUDA 上的数论变换（NTT）做超大十进制整数乘法。

- 6000 万位 × 6000 万位：**0.37 s**
- 2.68 亿位 × 2.68 亿位：**1.5 s**
- 5.37 亿位 × 5.37 亿位（32 位算术下的极限）：**3.3 s**，结果 10.7 亿位（两项都不含落盘）

GTX 1660 SUPER 6 GB / CUDA 13.1 / i3-12100F / 16 GB 内存。计时取同机三次最小值，
机器上同时开着浏览器和编辑器。

## 环境

- Windows + Visual Studio 2022（“使用 C++ 的桌面开发”工作负载）
- CUDA 12.x 或 13.x
- 任意 NVIDIA 显卡：构建时按本机算力生成代码

> CUDA 13 起不再支持 Maxwell（sm_50）及更早架构。老卡需要留在 CUDA 12.x。

## 构建

```powershell
./build.ps1              # 按本机显卡算力编译
./build.ps1 -Arch 86     # 指定算力
```

脚本自己找 Visual Studio 和 CUDA，不需要先开 Developer PowerShell；CUDA 不支持目标
算力时会直接说明原因。

源码是 **UTF-8 带 BOM**。编辑时别把 BOM 去掉：nvcc 按系统代码页读源文件，没有 BOM
时中文注释和字符串会被读坏，报“missing closing quote”。

## 运行

```powershell
./ntt_gpu.exe                    # ./input.txt -> ./output.txt
./ntt_gpu.exe in.txt out.txt
./ntt_gpu.exe in.txt -           # 结果写标准输出（诊断改走标准错误）
Get-Content in.txt | ./ntt_gpu.exe - -    # 全走管道
./ntt_gpu.exe --bench            # 内置压测：100 万 / 1000 万 / 6000 万三档
./ntt_gpu.exe --bench 200000000  # 指定位数
./ntt_gpu.exe --help
```

- 输入：**恰好两行**十进制数字，允许前导零；兼容 UTF-8 BOM、CRLF、单独 CR、末行没有换行
- 输出：一行十进制结果，LF 换行
- 退出码：`0` 成功，`1` 输入或 GPU 错误，`2` 参数错误

stdout 打印十一个诊断字段，加起来就是 total：

```text
left_digits=60000000
right_digits=60000000
result_digits=119999999
transform_size=16777216
input_ms=27.3
init_ms=127.4
gpu_phase_ms=116.6
crt_ms=35.9
carry_ms=46.3
output_ms=20.4
total_ms=374.5
```

`init_ms` 是 CUDA 上下文初始化的时间，要一百多毫秒，所以程序把它和读文件、解析
并行起来；`total_ms` 已经把 `init_ms` 算进去，但在它被读文件掩盖掉的那部分不会重复计。

## 规模上限

变换长度受素数限制：支持 `2^27` 次单位根的素数，在 32 位算术下正好找到三个
（`15·2^27+1`、`17·2^27+1`、`29·2^27+1`），再大就得用 64 位模。所以 `2^27` 就是
天花板。基数取 `10^8`（一个 limb 八位），单边位数上限是 `4 × 2^27 = 5.37 亿`。

显存按每点 3 个 `u32` 计（left / right / 旋转因子表，共 12 字节），启动时取空闲显存的
75% 向下取到 2 的幂：

| 显存 | 最大变换长度 | 单边可算位数 |
|---:|---:|---:|
| 2 GB | `2^26` | 2.68 亿 |
| 6 GB | `2^27` | 5.37 亿 |

超出时在启动阶段就报“显存不足：需要 X MiB，只有 Y MiB 可用”，不会崩在 `cudaMalloc` 里。

上限用例的实测（`python test.py --huge`）：

| 阶段 | 耗时 |
|---|---:|
| 读入 + 解析 1.07 GB | 535 ms |
| 初始化（与读文件重叠） | 246 ms |
| GPU（3 个模数，`transform_size=2^27`） | 858 ms |
| CRT + 进位（1.34 亿个系数） | 1339 ms |
| 格式化输出 1.07 GB | 343 ms |
| **合计（不含落盘）** | **3321 ms** |

## 实测

6000 万位 × 6000 万位，三次取最小：

| 阶段 | 耗时 |
|---|---:|
| 读入 + 解析 120 MB | 27 ms |
| 初始化（与读文件重叠） | 127 ms |
| GPU（3 个模数 × 2 个方向） | 117 ms |
| CRT + 进位 | 82 ms |
| 格式化输出 120 MB | 20 ms |
| **合计** | **375 ms** |

2000 万位 × 2000 万位合计 **248 ms**。一半以上时间在读写和十进制转换上，GPU 只占小头。

## 算法

**三素数 + 基数 10^8**：一个 limb 八位十进制，卷积系数上界是 `(10^8-1)^2 × min(limb 数)`，
三素数乘积约 `1.79e28`，够用到单边 5.37 亿位。基数大了一倍，同样位数所需的变换长度
只有原来的一半，蝶形总量少近三成。

**三路 Garner**：每个系数 `x = r1 + p1·t1 + p1·p2·t2`，最大约 `6.8e23`，超过 64 位，
用三个 32 位字表示。拆 `x = q·10^8 + r` 时最高字不到 `2^16`，少做一次除法。

**radix-4 蝶形**：每级吃掉两个二进制位，全局访存趟数减半，4 点蝶形只要 3 次模乘
（radix-2 两趟要 4 次）。

**免位反转**：正变换用 DIF（自然序进、倒序出），逆变换用 DIT（倒序进、自然序出），
中间的频域点乘仍落在倒序上，整个流程不需要任何位反转置换。逆蝶形是正蝶形的逆运算，
只差 4 倍因子，由最后的 `1/n` 统一补上。

**级计划**：`2^L` 拆成一串 radix-4 级加至多一个 radix-2 级；最内层不超过 `2^13` 点
的那几级一次读进共享内存做完，只花一趟全局访存。

**旋转因子**：每级只存 `w^j` 一张表，`w^2j`、`w^3j` 用两次模乘现推——这里访存比算术贵。

**模乘**：Barrett，预存 `floor(2^64/p)`，两个因子都小于模数时商最多小 1。余数在 64 位里
比较完再截断：`3892314113` 这种 `2p > 2^32` 的素数，先截断再比较会算错。

**并行 I/O**：解析和格式化都按 limb 切块分给几个线程，这两段原来是端到端时间的一半。

**CRT 分块**：余数合成全并行，进位天然串行，所以按 419 万系数一块：并行算
`q·10^8 + r`，串行走一遍只做一次加法和一次除法，内存占用与输入规模无关。

**锁页内存**：残留数组用 `cudaHostAlloc` 分配。分页内存做 D2H 只有 1.8 GB/s，锁页能到
10 GB/s 以上。

**自乘**：两行输入相同时只做一次正变换、频域直接平方，省掉三分之一变换。

## 测试

```powershell
python test.py            # 22 个用例，秒级
python test.py --big      # 追加 100 万位
python test.py --fuzz 200 # 追加 200 组随机尺寸（含 limb 边界）
python test.py --huge     # 追加 5.37 亿位上限用例，约 4 GB 内存
```

标准答案是 Python 自带的大整数，逐字节比较。覆盖 `0`、前导零、全 `9`（最长进位链）、
10 的幂、不平衡输入、BOM/CRLF/CR/末行无换行，以及各种非法输入的错误信息。上限用例
用 `(10^k-1)^2` 的闭式解校验，不靠 Python 硬乘。

## 设计取舍

- **一律走 NTT**：不做“小输入退回 CPU 竖式”“1×n 退化成标量乘”这类形状特化。乘两个
  50 位数也要付一次 CUDA 上下文初始化（约 130 ms），这是诚实的代价。
- **不平衡输入也跑完整 NTT**：1 位 × 1 亿位和两个 1 亿位付一样的钱。
- **单文件**：一个 `.cu` 编完，没有头文件和中间层。
