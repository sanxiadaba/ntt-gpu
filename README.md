# ntt-gpu

用 CUDA 上的数论变换（NTT）做超大十进制整数乘法。

两个 6000 万位的数相乘约 **0.83 s**，2.68 亿位相乘约 **4.3 s**（GTX 1660 SUPER 6 GB）。

## 环境

- Windows + Visual Studio 2022（“使用 C++ 的桌面开发”工作负载）
- CUDA 12.x 或 13.x
- 任意 NVIDIA 显卡：构建时按本机算力生成代码

> CUDA 13 起不再支持 Maxwell（sm_50）及更早架构。老卡需要留在 CUDA 12.x。

## 构建

```powershell
./build.ps1              # 按本机显卡算力编译
./build.ps1 -Arch 86     # 指定算力
```

脚本自己找 Visual Studio 和 CUDA，不需要先开 Developer PowerShell；CUDA 不支持目标算力时会直接说明原因。

源码是 **UTF-8 带 BOM**。编辑时别把 BOM 去掉：nvcc 按系统代码页读源文件，没有 BOM 时中文注释和字符串会被读坏。

## 运行

```powershell
./ntt_gpu.exe                    # ./input.txt -> ./output.txt
./ntt_gpu.exe in.txt out.txt
./ntt_gpu.exe --help
```

- 输入：**恰好两行**十进制数字，允许前导零；兼容 UTF-8 BOM、CRLF、单独 CR、末行没有换行
- 输出：一行十进制结果，LF 换行
- 退出码：`0` 成功，`1` 输入或 GPU 错误，`2` 参数错误

stdout 打印九个诊断字段：

```text
left_digits=60000000
right_digits=60000000
result_digits=119999999
transform_size=33554432
input_ms=323
gpu_phase_ms=143
crt_carry_ms=116
output_ms=93
total_ms=835
```

## 规模上限

两个素数都支持到 `2^27` 次单位根，这是数学上限。显存按每点 3 个 `u32` 计（left / right / 旋转因子表，共 12 字节），启动时取空闲显存的 75% 向下取到 2 的幂：

| 显存 | 最大变换长度 | 可算位数（两侧相同） |
|---:|---:|---:|
| 2 GB | `2^26` | 约 1.34 亿位 |
| 6 GB | `2^27` | 约 2.68 亿位 |

超出时在启动阶段就报“显存不足：需要 X MiB，只有 Y MiB 可用”，不会崩在 `cudaMalloc` 里。

## 实测

GTX 1660 SUPER 6 GB / CUDA 13.1 / i3-12100F / NVMe，6000 万位 × 6000 万位，多次运行取中位数：

| 阶段 | 旧（radix-2） | 现（radix-4） |
|---|---:|---:|
| 读入 + 解析 | ~300 ms | ~320 ms |
| GPU（NTT） | ~345 ms | **~143 ms** |
| CRT + 进位 | ~150 ms | **~116 ms** |
| 写输出 | ~274 ms | **~93 ms** |
| **合计** | **~1212 ms** | **~835 ms** |

`a ≠ b` 的一般情形（两行不同，正变换要做两次）：GPU 阶段 ~213 ms，合计 ~825 ms。

`2^27` 上限实测（2.68 亿位 × 2.68 亿位，结果 5.36 亿位，整程序 4.30 s）：

| 阶段 | 耗时 |
|---|---:|
| 读入 + 解析 536 MB | 1872 ms |
| GPU（`transform_size=2^27`） | 756 ms |
| CRT + 进位 1.34 亿个系数 | 783 ms |
| 写输出 536 MB | 340 ms |

端到端一半以上花在读写和十进制解析上，GPU 只占小头。这个程序的价值在 NTT 本身，不在 I/O。

## 算法

**系数表示**：按 10^4 切成 limb，两个素数下各做一次卷积，再用 CRT 还原精确系数。基数 10^4 时卷积系数上界是 `(10^4-1)^2 · min(limb 数)`；两个 6000 万位数约 1.5e15，而两个素数的乘积 4.59e18 够用，且小于 `2^63`，CRT 全程 64 位算术不溢出。

**素数**：`2281701377 = 17·2^27+1`（原根 3）、`2013265921 = 15·2^27+1`（原根 31）。

**radix-4 蝶形**：每级吃掉两个二进制位，全局访存趟数从 14 降到 7，4 点蝶形只要 3 次模乘（radix-2 两趟要 4 次）。

**免位反转**：正变换用 DIF（自然序进、倒序出），逆变换用 DIT（倒序进、自然序出），中间的频域点乘仍落在倒序上，整个流程不需要任何位反转置换。逆蝶形是正蝶形的逆运算，只差 4 倍因子，由最后的 `1/n` 统一补上。

**级计划**：`2^L` 被拆成一串 radix-4 级加至多一个 radix-2 级；最内层不超过 `2^12` 点的那几级一次读进共享内存做完，只花一趟全局访存。

**旋转因子**：每级只存 `w^j` 一张表，`w^2j`、`w^3j` 用两次模乘现推——这里访存比算术贵得多。逆变换另存一张 `w^-j` 表。

**模乘**：Barrett，预存 `floor(2^64/p)`，两个因子都小于模数时商最多小 1，一次条件减法即可。`add_mod` 先跟 `p-b` 比较，避免 `a+b` 溢出 32 位（`2·p > 2^32`）。

**融合**：`1/n` 缩放乘进频域点乘，省掉一趟全数组读写。

**自乘**：两行输入相同时只做一次正变换、频域直接平方，省掉三分之一变换。

**锁页内存**：残留数组用 `cudaHostAlloc` 分配。分页内存做 D2H 只有 1.8 GB/s，锁页能到 10 GB/s 以上——128 MB 拷两次的差距就是 100 ms 量级。

**小输入快速路径**：较短一侧不超过 64 个 limb、且乘算次数不超过 200 万时，直接在 CPU 上做竖式乘法。乘两个 50 位数不必付 CUDA 上下文初始化的 190 ms。

## 测试

```powershell
python test.py          # 秒级，22 个用例
python test.py --big    # 追加 100 万位用例
```

标准答案是 Python 自带的大整数，逐字节比较。覆盖 `0`、前导零、全 `9`（最长进位链）、10 的幂、不平衡输入、BOM/CRLF/CR/末行无换行，以及各种非法输入的错误信息。

## 已知限制

- 读入解析与写输出仍占端到端一半以上，都没有并行化
- 不平衡输入（1 位 × 1 亿位）仍按完整 NTT 跑，没有退化成线性扫描
- 只在本机（sm_75）与 `2^27` 上限上实测过；其它算力只保证能编译
